# 文件导入与本机识别 · 2026-10-01

## 使用与保存

备忘正文、普通流程的正文和步骤说明、AI 流程材料均提供「添加图片 / 文件」。默认勾选「导入时在本机识别内容」：导入原件，再将识别文字和能拆出的内嵌原图放进当前位置。拖入文件、粘贴图片使用同一路径；取消勾选则仅加入附件。

文本与 Office/PDF 结构提取仍在本机执行；图片、扫描 PDF 页及 Office 内嵌图片优先发给当前配置的多模态 AI 逐张转录，失败时回退到本机 PaddleOCR。AI 只收到待识别的图片，不上传原件整份文件；可在知识库界面核对这项数据范围。普通编辑沿用原有自动保存行为；AI 材料点击生成后才发送，AI 生成草稿仍需明确确认保存。导入期间输入、光标或焦点变化会报告错误，不能用旧内容覆盖新编辑。

识别失败保留原件链接并显示真实错误。识别文字超过编辑位置剩余额度时，完整结果作为 Markdown 文件保存，不截断文字；当前位置只放可容纳的链接，其余链接在「本次导入结果（尚未放进当前内容）」中可查看或另存。该结果区不是已保存备忘内容，需用户另存或放进合适位置。

## 格式和边界

| 格式 | 本机识别 | 保留与限制 |
| --- | --- | --- |
| Word DOCX | 正文段落、表格文字、可识别的内嵌图片 | 原件保留；页眉、脚注未导入，文本框与原版式不保证还原 |
| Word DOC | 尚未实现，明确报错 | 请另存为 DOCX，不伪装成识别成功 |
| Excel XLSX / XLS | 工作表名称及单元格值 | 公式、图表、合并单元格与原版式未重建；需核对表格列和数量 |
| 带文字层 PDF | 提取每页文字 | 原件保留，版式及内嵌图片未拆分 |
| 扫描 PDF | Windows PDF 页面渲染；多模态 AI 优先，PaddleOCR 兜底 | 每张扫描页单独识别；原件保留；识别失败不标为可检索 |
| PNG / JPEG 等支持的图片 | 多模态 AI 优先，PaddleOCR 兜底 | 原图保留；两引擎都失败时明确报错；Windows OCR 已移除 |
| UTF-8 TXT / Markdown / CSV | 读取文字 | 其它编码需先转换；CSV 作为文字，不自动推断业务流程 |

单原件仍为 20 MiB；Office 解压总量最多 40 MiB、2000 条目；单件识别文字最多 100000 字，内嵌图片最多 100 张且总计 20 MiB，PDF 最多 100 页、Excel 最多 100 工作表与 100000 单元格。另受编辑位置字数限制：流程步骤 5000 字、正文 100000 字、AI 原始材料 80000 字和正文文字 20000 字；AI 文件文字合计最多 100000 字、选中资源总大小 20 MiB。超限报错，不静默截断。旧 XLS 的稀疏坐标范围也受限制，超过时可缩小使用范围或另存 XLSX。

## AI 文件输入

2026-10-01 核对官方资料：[DeepSeek Harness](https://www.deepseek.com/zh/harness/) 通过插件和工具处理文档与表格；公开 [Files API](https://api-docs.deepseek.com/guides/files_api/) 当前列出的上传格式是 JPEG、PNG、GIF、WebP，未列出 DOCX、XLSX、PDF。因此不能笼统说“DeepSeek 不能读 Word”，也不能把文档原始二进制当成该接口已承诺接受的输入。Lumen 接上本机文档读取后，用户直接选择原文件即可，无需手动转换正文。

原始 Word、Excel、PDF 链接保留。当前服务不能直接接受相应格式时，后端先在本机提取文字，构造同一原件编号的临时文本输入；数据库中的原件不被替换。原始图片与已拆出的图片仍按所选引用发送。只分析本次选择的材料，不扫描其它业务记录。

OCR 结果是提取文本，不保证完全正确；需要核对原件。普通模式把材料放进编辑器；AI 模式进一步按所选内容整理步骤，用户核对负责人、先后顺序、数量及原图归属。

负责人为可选内容：有明确材料才填写，没有时留空，不强制「待确认」。普通保存同样接受空白负责人，已保存旧流程的负责人不自动改写。
