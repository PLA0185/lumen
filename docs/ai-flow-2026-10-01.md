# 文字、聊天记录与截图生成流程 · 2026-10-01

## 使用

进入「备忘与流程 → AI 生成流程」，粘贴业务说明、微信聊天文字或截图，也可以添加本地文件。点击「生成流程草稿」后，在已有流程编辑器核对标题、分类、背景、负责人和操作步骤，再点击「确认保存流程」。

材料输入区增大为 240px 高，说明、输入与附件、服务信息、操作按钮分区；小窗口可滚动。生成失败显示实际错误并保留材料，可以重试或取消。

## 数据范围和保存

0.4.6 的图片预览提供「移除图片」，完整文件预览也可移除文件。操作仅删除当前输入框内该资源的 Markdown 引用，不删除资源本体或其它记录中的引用；同一输入内重复引用同一资源会一起移除。失效图片也能移除，只读、生成中或导入中没有移除入口。

文字和图片可以混用：按聊天顺序粘贴文字，在相关文字旁加入原图。整段聊天截图只能提供截图中可见的内容，「+1 more」折叠部分和模糊缩略图不能代表完整原图；日期修改等消息需保留上下文，关联不清楚应人工核对。Lumen 不自动展开或读取微信。

- 只有本次材料文字和其中明确引用的本地资源发送到当前设置的 AI 服务，生成命令不读取其它业务记录。
- 返回新流程草稿，不接受模型指定旧记录 ID；步骤 ID 由本机生成。不写任务或覆盖已有备忘。
- AI 草稿及手动修改都暂停自动保存，只有确认才写入新记录。普通手动新建、编辑的自动保存不变。
- 原始材料及截图链接附在正文末尾；缺少负责人、操作细节标为「待确认」。要求模型区分最终约定、否决方案及闲聊，但模型准确性仍需用户核对。
- 非 JSON、无步骤、空步骤标题、超出长度/步骤上限、引用未选择资源的模型返回明确错误。
- API 密钥仅保存到系统凭据管理器，数据库只存服务地址、模型及配置状态。真实密钥与测试图片均未进入仓库。

## 实际验证

0.4.7 修复输入文字导致预览闪动：仍被引用的资源及 Blob URL 在同一预览中复用，新增段落也不重新读取图片；移除或切换内容释放预览缓存。一次材料的本机文件上限改为 600 个、总大小仍为 20 MiB；正文最多 20000 字，含资源标记的原始输入最多 80000 字。600 是数量防护边界，不代表任何大小、文件名或模型的 600 份材料都可发送，也没有进行 600 图真实模型请求。实际资源读取及请求构造验证使用 15 张有效图片。

- 前端入口测试先在未实现功能时失败，实施后通过。完整本地门禁实际执行：冻结安装、类型检查、226 项前端测试、前端构建、Lint、版本一致性、Rust 格式、420 项 Rust 测试、全目标全特性 Clippy。
- 独立代码审查发现图片导入中可能漏发截图、确认放弃旧编辑后取消生成仍可能自动保存旧草稿；两项均用真实受控组件测试先复现失败，再修复为导入完成才能生成、确认放弃立即还原/清除草稿，重新执行全部门禁。
- `tools/verify_ai_flow_ui.py` 在无云同步的空白隔离目录完成 10 项原生鼠标验收：无效响应报错、保留材料、重试、负责人缺失、生成和编辑不自动保存、明确确认、新建且不覆盖、仅发送选中材料及图片原始字节。它使用本机 HTTP 故障服务，**不代表真实模型验收**。
- 原生脚本曾因图片异步加载后按钮移动导致请求未发出，以及脚本选择器引号错误失败；未计为通过。等待本地图片实际加载、滚动后验证按钮命中，并修正选择器后，在全新隔离目录完整通过。
- 使用用户确认的 DeepSeek 服务及其本机密钥，真实模型列表包含 `deepseek-flash`、`deepseek-v4-pro`；`deepseek-flash` 分别完成聊天文字与纯图片材料的生成。图片请求文字没有提供图片正文，结果包含截图中的型号/数量核对、库存与缺货、发货及物流单号。两次生成前后隔离备忘列表一致，没有保存。
- 真实模型内容存在需要人工核对的表述，例如概述可能仍写负责人待确认而步骤已有角色；保留原始图片便于核对，不宣称 AI 无误。
- 0.4.6 的移除功能两项测试先因没有按钮失败，实施后全部通过；完整本地与源码 CI 门禁实际通过 229 项前端和 420 项 Rust 测试。正常图片、失效引用、只读限制、文字和另一图片保留均有组件验证。
- 主界面窄窗口顶栏曾把标题挤到 0px，实际布局断言失败；增加标题正常宽度和工具换行后，正式安装的 0.4.6 在 800、984、1280、1600px 宽度下标题横排、工具均位于顶栏边界内。正式程序重开后复查，无需临时样式补丁。
