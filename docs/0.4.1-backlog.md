# Lumen 0.4.1 Backlog

本清单只收录 0.4.0 RC 收口期间发现、但不构成 P0/P1 的事项。它们不阻断当前 RC，进入 0.4.1 排期后再做。

## P2

| 项目 | 原因 | 当前影响 | 0.4.1 建议 |
| --- | --- | --- | --- |
| 1920×1080 与 2560×1440 下的主列表内容宽度 | 当前以可读行长为优先，宽屏两侧留白较多 | 不影响操作，信息密度偏保守 | 提供“舒适/紧凑”密度设置，宽屏允许双栏或更宽列表 |
| 月历高密度日期格 | 同一天任务多时标题会省略 | 数量与日期仍准确，需进入当天查看完整标题 | 增加“更多 N 项”入口和当天抽屉 |
| 看板低密度布局 | 任务集中在一列时其它列留白明显 | 工作流清楚，但空间利用率一般 | 研究可选的紧凑列宽和横向滚动策略 |
| 设置页信息架构 | 功能增多后，部分标签页仍较长 | 功能均可达，首次查找成本偏高 | 加页内目录和设置搜索 |
| Windows 原生文件选择器自动化 | CDP 只能驱动 WebView，不能可靠驱动系统文件选择窗口 | 用户手动添加附件可用，自动验收链路未覆盖该一步 | 增加 WinAppDriver/UIA 辅助验收或测试专用文件注入接口 |
| AI 真实服务商端到端验收 | RC 环境没有可用密钥，不能安全写入凭据管理器构造差异 | 本地配置、预览、provider 独立状态已有单元和无密钥验收；真实请求未做 | 在专用测试账号与预算上跑预览、应用、限流和鉴权错误链路 |

## P3

| 项目 | 原因 | 当前影响 | 0.4.1 建议 |
| --- | --- | --- | --- |
| 日历、看板、悬浮窗的个性化密度 | 当前采用统一视觉令牌和固定密度 | 默认体验一致，个性化空间有限 | 在不增加主路径复杂度的前提下提供密度预设 |
| RC 截图自动基线比较 | 本轮使用真实渲染截图加人工检查 | 能发现明显布局问题，不能自动识别细微视觉回归 | 为稳定区域加入像素差阈值与人工更新流程 |
| 更多时区快捷项 | 当前提供系统、中国、美国东部、英国、UTC 与自定义 IANA | 常用场景已覆盖，少数地区仍需输入 IANA 名称 | 根据用户反馈扩充快捷项，并保持底层 IANA 值不变 |

## 收录规则

- 新条目必须写明用户影响和验收方式。
- 若确认会导致数据丢失、基本流程无法完成或错误结果，则升级为 P0/P1，不能继续留在本清单。
- 0.4.1 开工时重新排序；本文件不代表已承诺的发布时间。
