# Lumen 跨平台界面重构设计

## 目标

把 Lumen 现有分散的界面整理成一套一致、易读、反馈明确的设计系统，并针对 Android 与 Windows 的输入方式分别优化。保留现有数据、页面能力和深色/浅色主题；本轮重点是信息层级、页面骨架、导航、控件、图标、动效与可访问性，不借 UI 改造重写业务逻辑。

## 用户目标与约束

- 用户明确要求以 Apple 设计指南的原则审视整个项目，同时区分 Android 与 Windows 端。
- 用户过去反复指出页面挤压、空白失衡、选中态颜色奇怪、操作状态看不清、按钮交互不一致、流程节点导航高亮/悬停不一致、侧栏内容已显示完整仍出现滚动等问题；这些属于本轮回归检查范围。
- 保留现有深色和浅色主题及用户可调外观；提升暗色界面次级文字的可读性，强调色只表达主要操作或选中状态。
- 不复制 Apple 专有视觉材料、SF Symbols 或 Liquid Glass；从指南提取清晰、一致、内容优先、可访问、尊重输入设备的原则。
- 不增加新的 UI 依赖，不改变业务数据或同步协议。

## 设计方案

### 共用视觉系统

- 统一颜色语义、排版层级、间距、圆角、边框、阴影、控件高度和动效时长，继续使用现有 CSS 变量及自绘 SVG 图标集。
- 将主操作与普通操作区分；选中导航用低干扰表面、清楚的侧边标记和图标状态，不让整排紫色填充或紫色正文争夺注意力。
- 次级文字在亮/暗主题下都保持清晰；状态同时通过文字/图标/形状表达，不能只靠颜色。
- 所有可交互控件统一 hover、pressed、focus-visible、disabled、loading 状态；鼠标提示只作增强，触控与键盘路径本身完整。
- 保留简短、可预测的过渡；系统减少动态效果和应用“关闭动画”设置都必须停止非必要动画。

### Windows

- 使用稳定的左侧分组导航、独立页面标题和可换行的命令区；窄窗口下命令折叠或换行，不裁切关键操作，也不出现横向“硬等”滚动条。
- 键鼠优先：明确 hover、键盘焦点、快捷键提示和拖放状态；保留适合高 DPI 与可调整窗口的桌面密度。
- 页面内容使用可预测的宽度和间距，让列表、表单、知识库答案和流程画布按内容扩展，不在超宽窗口留下无意义空栏。

### Android

- 紧凑窗口使用 3–5 项底部主导航，其余入口进入清晰的“更多”导航；较宽窗口自动切换为侧边导航。
- 触控优先：交互目标至少 44 CSS px，使用系统安全区，提供足够的纵向滚动区；不把 hover 作为唯一反馈。
- 页面默认纵向单栏，表单字段易点选，长操作有持续的文字进度/结果；横屏或大屏再使用两栏。

## 页面范围

全局壳层与侧栏/顶栏、任务列表与卡片、周期任务、日历、看板、项目/标签、备忘与流程画布、知识库问答、食谱与采购、AI 助手、统计、设置、弹窗/对话框、空/加载/错误/成功状态。

## 验收标准

1. Android 窄屏与宽屏导航按窗口宽度正确切换，Windows 继续显示持久侧栏；关键页面没有横向内容溢出或被顶栏遮挡。
2. Windows 和 Android 的按钮、导航、输入框、列表条目和流程节点的选中/悬停/按下/键盘焦点状态一致且可区分，点击目标没有遮挡。
3. 主题色只用于明确的主操作、选中或语义状态；浅色、深色和用户自定义主题下文字、图标与边框仍可辨认。
4. 主要操作、表单、知识库结果与流程画布在 Android 触控和 Windows 键鼠下均可使用；减少动态效果设置生效。
5. 用户提到的主要历史 UI 问题都由代码或可复现的 UI 验收覆盖；任何未能实机验证的平台/窗口尺寸在工作记录中明确列出。
6. 完整执行仓库 AGENTS.md 门禁，记录工作日志，分主题提交并推送。

## 官方设计依据（2026-10-09 检索）

- Apple 设计入口与《人机界面指南》：[Apple 开发者设计](https://developer.apple.com/cn/design/)；采用其清晰、简单、灵活、细节到位的原则，以及一致配色、充足对比、目的明确且可关闭的动效建议。
- Android 自适应导航：[布局和导航模式](https://developer.android.com/design/ui/mobile/guides/layout-and-content/layout-and-nav-patterns?hl=zh-cn)：紧凑屏使用 3–5 项导航，宽屏切换侧边导航。
- Windows 设计：[Design Windows apps](https://learn.microsoft.com/zh-cn/windows/apps/design/)：响应式布局、导航、图标、动效、命令和无障碍。
