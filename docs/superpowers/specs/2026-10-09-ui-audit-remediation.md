# Lumen 全界面自查与可读性整改

## 目标

修复当前界面里用户无法区分备忘与流程、长备忘读不全、空页面留白失衡、说明信息堆成长段，以及其他经实机逐页检查发现的显示/操作不清问题。让常用页面在 Windows 和 Android 尺寸下都能看清内容、找到操作，并且不需要猜测状态。

## 已复现问题

- 侧栏只有“备忘与流程”一个入口，备忘与流程共用列表、搜索、分类筛选、回收站和空状态；知识库打开流程也导航到混合页。
- Markdown 通用预览将高度限制为 260px。备忘阅读正文继承这个限制，长内容被困在嵌套滚动区；真实 WebView 中 289px 正文的 `scrollHeight` 大于 260px。
- 备忘页文档面板强制 `min-height: 420px`，空态文本很少仍占大块空间；移动布局还把列表高度固定在 220px。
- 知识库的隐私、云同步和图片 OCR 说明以一整段长文横跨页面，难扫读。
- 空看板的每列保留较大的空白拖放区，零任务时视觉上像内容缺失。
- 食谱汇总在训练消耗为 0 时仍显示减号，形成“−0 千卡”。

## 约束与设计

- 新增独立“备忘”和“流程”视图；继续使用现有 `memo_documents.kind` 数据，不改数据库、备份或云同步格式。
- 两个视图分别搜索、分类筛选、显示计数和管理回收站；共用编辑、版本、删除/恢复与原有保存逻辑。知识库来源点击直接进入流程视图并定位步骤。
- 备忘正文和流程步骤正文按自然内容高度展开，由页面主滚动区承载长内容；摘要和检索结果等短预览仍保留自己的合理高度上限。
- 空状态按其实际内容自然定高并给出准确入口；没有可筛选分类时隐藏无效筛选控件。
- 长隐私说明以简洁摘要呈现，完整说明收纳在可访问的折叠区域。
- 空看板保留可拖放能力，但空列缩至内容所需高度；热量汇总将摄入、加餐、训练扣减的数字表达保持一致，零值不显示负号。
- 扫查全部主视图、对话框和两类窗口宽度，重点检查标题/工具栏换行、正文截断、横向溢出、空态留白、说明密度和控制目标；只改可复现的问题，不做无目标的统一重绘。
- 不增加依赖、不动业务计算和持久化；遵循系统减少动态效果、键盘焦点和触控目标要求。

## 验收标准

1. Windows 侧栏有独立的“备忘”和“流程”；Android 主导航的流程入口及“更多”中的备忘入口均有正确选中态。
2. 每种视图只显示同类型记录、搜索结果、分类和回收站数据；知识库流程来源可正确打开流程。
3. 长备忘和长流程步骤在阅读模式中没有固定高度或内嵌滚动截断；用户可用页面滚动读到末尾。
4. 空状态不保留 420px 固定空白；没有分类选项时不显示无效筛选器；知识库长说明可折叠。
5. 空看板没有过大的空占位，“训练消耗 0”显示为无符号的零。
6. 实际 WebView 桌面宽度与紧凑/宽屏 Android CSS 尺寸没有横向溢出或关键内容覆盖；所有可见文本可读、主操作明确。
7. 前端与 Rust 门禁、真实 WebView UI 验收、GitHub CI 通过；工作记录完整追加并推送。
