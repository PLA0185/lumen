# 食谱、热量与采购清单：设计与研究

## 目标

在 Lumen 内建立本地优先、可云同步的食谱、每日饮食计划与实际热量记录，以及采购待办清单；食物热量必须经过真实联网检索并由用户已配置的 AI 服务基于检索证据归一化。统一视觉基础，但按 Android 的触控与紧凑窗口、Windows 的键鼠与可调整窗口分别呈现。

## 已确认的产品规则

- 每日热量目标由用户手动设置，首值为空；不推测年龄、身高、体重、性别或减重目标。
- 日计划与实际记录分开。食谱可安排到早餐、午餐或晚餐；没有标为“已吃”的食物只显示为计划，不进入实际摄入。
- 已吃的基础餐、加餐、训练消耗分开汇总。训练消耗记录是用户明确录入的活动和热量，不由 AI 推算。净摄入 = 已吃基础餐 + 已吃加餐 - 已记录训练消耗。
- 新增或修改食物名称时，必须调用在线搜索并让当前配置的模型依据结果给出热量和来源。每份记录保存名称、份量（克）、每 100 克千卡、计算后整数千卡、来源标题、URL 和核实时间。改份量只重算，不重复联网。没有有效证据、没有可用的联网搜索密钥、AI 未配置或调用失败时，给出具体原因并且不写入/不改变原记录。
- 热量算术只在本机确定性计算：`round(克数 × 千卡/100克 ÷ 100)`；训练则直接使用用户录入的 kcal。模型不能直接决定总计。
- 采购清单支持手动增删、数量单位、分类、备注和完成状态；从食谱添加时按“名称+单位”合并数量，勾选完成不删除记录。
- 导入复用现有文件提取器和 20 MiB 单文件边界。用户先选“本机识别”或“AI 整理”；两种方式均先显示草稿与异常项，确认后才写入。AI 模式会把提取正文及需要识别的内嵌/扫描图片发给配置的 AI 服务；本机模式不联网传内容。Windows 本机图片 OCR 使用 PaddleOCR，Android 文字文件可本机解析，图片及扫描件需要切到 AI 整理；Android 扫描 PDF 的本机 OCR 暂不可用。
- 食谱、食物记录、日计划、采购条目、目标均进入完整备份和恢复，并随云同步“全部业务数据”加密同步；“仅任务”与“仅备忘与流程”不传饮食数据。本轮没有新增饮食专属同步开关。搜索密钥仅保存在当前设备系统凭据库，不备份、不云同步；短时检索候选仅本机保存。
- 导入和搜索时显示当前阶段、错误与外部发送的数据范围；不会把失败写成成功。

## 数据与界面

新增 SQLite 表 `nutrition_preferences`、`recipes`、`recipe_ingredients`、`nutrition_entries`、`shopping_items`。`nutrition_entries` 保存实际或计划条目的不可变热量快照；`recipe_ingredients` 保存 AI 检索后的来源快照。所有用户可编辑的写入有输入边界校验并使用事务，项目沿用正式迁移机制和同步事件模型。

新增侧栏“食谱与采购”视图：顶部日期/日目标，紧凑热量摘要（基础餐、加餐、训练消耗、净摄入、剩余），下方每日计划与实际记录，再下方可切换的食谱与采购清单。搜索候选和文件导入都使用可见的来源/确认步骤。窄屏纵向单列；宽屏使用两栏内容，支持键盘、屏幕阅读器和减少动态效果偏好。

## 平台设计原则

- 共用一套颜色、排版、间距、焦点和语义化矢量图标令牌；不复制 SF Symbols。复用现有 SVG `Icon` 集并补充营养/购物图标，明确悬停、键盘焦点、按下、禁用和加载状态。
- **Apple HIG 是体验原则参考，不是视觉皮肤照搬**：功能清晰、内容优先、一致反馈、易触达、可访问、尊重隐私；Liquid Glass 只适用于 Apple 平台。本项目没有 Apple 平台目标，不复制其专有材料效果。
- Android 窄窗口用底部主导航和“更多”抽屉；宽窗口（900 CSS px 起）切到完整侧栏。页面按窄屏单列、触控目标与系统安全区布局，不依赖鼠标悬停。
- Windows 保持持久侧栏和顶部命令区，支持鼠标悬停反馈、键盘焦点/快捷键、可调整窗口与高 DPI。共用主题令牌，但使用 Windows 熟悉的密度和命令行为。
- 动效短、表达状态变化、支持 `prefers-reduced-motion` 和现有“关闭动画”设置；不以动画代替保存/搜索结果文字。

## 联网营养检索

检索由 Tavily Search API (`POST https://api.tavily.com/search`) 获取实时证据，返回的候选网页再交给已配置的 AI 服务进行结构化归一化。AI 输出只可引用 Lumen 提供的搜索结果索引；后端验证 index、名称长度、热量范围（0–900 kcal/100g）、来源 HTTPS URL 与有限结果数。UI 将模型候选和可打开的来源展示给用户确认。请求只发送食物查询，不发送日记、份量、健康档案或整份文件。Tavily 需要用户自行创建独立 API Key。官方定价页当前列出的免费档为每月 1,000 API credits、无需信用卡；Pay As You Go 页面显示 `$0.008/credit`，请求消耗随接口选项变化，价格和额度可能调整。搜索设置链接到 [官方定价页](https://www.tavily.com/pricing)，不承诺固定的每次搜索费用。

选择 Tavily 是因为当前 DeepSeek / 自定义 Chat Completions 调用没有通用在线搜索工具，而现有 OpenAI Responses `web_search` 无法作为所有配置的通用能力；Tavily 做检索，用户原有模型做证据理解，职责分开。Windows 密钥保存在系统凭据管理器；Android 使用 Android Keystore 保护的原生安全凭据库。密钥不向 React 暴露，不提交、备份或加入同步。

## 错误与隐私

- HTTP 断网/429/无结果/无可引用证据/模型 JSON 非法/凭据库错误均返回明确错误，不写半条记录。
- 文件解析产生的草稿默认暂存在页面内存；取消或应用重启不写入清单。
- 文件导入 AI 模式须在操作按钮旁明确提示发送范围（提取正文和需要 OCR 的图片）；AI 查询只向搜索服务发送食物查询，并向已配置模型发送食物查询和公开搜索摘录。
- 不依赖 AI 作为计量器。训练、每日合计、计划状态及购物数量合并均由 Rust/前端确定逻辑处理并有行为测试。

## 验收条件

1. 首次打开可手动设置目标；无目标和空数据都有解释性状态。
2. 变体食物名经在线搜索后，用户能选择结果、查看来源并按克数记录；AI 不可用时不出现猜测热量。
3. 计划不混入已吃合计；基础餐、零食、训练消耗和净值计算口径正确；修改克数即时重算。
4. 食谱可维护配料、按份量算热量、加入每日计划并汇总到采购清单。
5. 本机和 AI 两种采购文件导入都能预览/撤销；CSV/JSON/文本及现有解析器支持的 DOCX/XLSX/PDF/图片遵循现有边界。
6. 迁移前一致性快照；完整备份/恢复及“全部业务数据”同步往返验证；任务或备忘与流程专用范围不带饮食数据。
7. 宽窄屏、键鼠与触控样式、键盘焦点、可访问状态及减少动画偏好有自动验证；Android 构建若因本机工具链缺失无法完成，工作记录如实注明。

## 官方依据（2026-10-08 检索）

- Apple 设计资源与 HIG：[Apple 开发者设计](https://developer.apple.com/cn/design/)；其页面指向当前 HIG、官方设计资源和符号库。
- Android 自适应布局与导航：[布局和导航模式](https://developer.android.com/design/ui/mobile/guides/layout-and-content/layout-and-nav-patterns?hl=zh-cn)。官方建议主要导航控制在 3–5 项，大屏使用侧导航；当前按 900 CSS px 在底栏和侧栏之间切换。
- Windows Fluent、可访问性、窗口布局、图标、动效：[Windows 应用设计](https://learn.microsoft.com/zh-cn/windows/apps/design/)。
- Tavily [Search API 接入](https://help.tavily.com/articles/4840311948-tavily-search-api) 与[官方定价](https://www.tavily.com/pricing)。
- [Open Food Facts API](https://openfoodfacts.github.io/openfoodfacts-server/api/) 是社区贡献食品数据；此次不把单一社区库当成对所有地区/份量足够可信的唯一数据源。食品标签和同一食物的品牌/熟制差异需要可查看来源与用户确认。
