# 知识库云同步设计

## 目标与范围

让用户导入的知识库资料可以在接入同一 WebDAV 同步空间的电脑间使用。云端保存加密后的原件与已提取文本；接收设备复用提取文本重建本机分块和 FTS5 索引，不重新调用 AI/OCR。已有流程继续走“备忘与流程”同步。

只在同步范围为“全部业务数据”时上传、下载知识库资料。“仅任务及关联数据”与“仅备忘与流程”行为保持不变。资料单文件沿用 20 MiB 上限，提取文本沿用 100,000 字符上限。知识库资料删除使用现有业务版本墓碑和冲突保留规则。

## 协议与兼容性

- 知识库使用独立的加密 `devices/<device>/knowledge-head.json`，不扩充旧版严格校验的 `head.json`。
- 复用业务事件格式，但知识库事件批次与任务业务批次分别打包、分别建立父链；旧版只读 `business_heads`，不会下载或解析知识库批次。
- 每个知识来源按 SHA-256 建立稳定云端身份；原件资源也按 SHA-256 建立稳定身份。同一文件在不同设备重复导入时映射到各自本地行，不触发唯一键冲突。
- 知识库原件使用既有加密资源桶和空间恢复密钥。云端只保存密文。应用不会将整份资料发送给 AI；已有 AI/OCR 解析仍仅在初次导入设备运行。
- 知识库流不改变旧版 `head.json`。不识别独立知识库 head 的旧版本会继续同步既有任务、备忘与流程，但不会接收知识库资料；要在多台电脑间共享资料，各电脑都需要升级到支持该格式的版本。

## 数据与索引

同步完整 `knowledge_sources` 行（包括抽取正文、解析状态、告警和原件哈希），原件放单独加密资源。知识分块与 FTS5 是派生索引，不跨网盘传输；收到新增或更新来源后，在应用业务事务中按同一 `split_text` 规则重建。删除来源时由现有外键触发器删除本机索引；只有该原件没有被流程正文/步骤引用时才清理本地资源。若资料版本已入待上传队列，先保留原件以完成版本与删除墓碑上传，成功后自动清理未引用的原件；接收端如果只收到最终删除状态，也会清理未被流程引用的历史原件。

知识来源的云端规范化行不包含设备本地导入时间差异（统一规范时间字段），避免同一文件在两台电脑独立导入只因时间戳不同而产生冲突。正文或解析结果确有差异时，仍由现有冲突机制保留候选。

## 界面与反馈

知识库说明改为清楚说明同步范围、加密和索引重建方式；云同步设置说明知识库只随“全部业务数据”同步。现有待上传数包含新知识库事件。自动同步关闭时仍仅本机保存，用户可手动同步。

## 验收

1. 同步范围 All 在两台独立数据库间传播正文、原件、状态，并能在接收端通过知识库搜索找到文本。
2. 接收端删除知识来源会传播墓碑；被流程引用的原件不会被误删。
3. 两台设备导入同一 SHA-256 文件不会产生重复资料或伪冲突；真实正文差异仍进入冲突。
4. Tasks/Memos 范围不会上传或下载知识库事件。
5. 知识库批次不进入旧 `head.json` 的 `business_heads`；知识库文件名和原文在云端均不可读。
6. 丢失、损坏或摘要不匹配的原件会让接收失败并保留已存在的本地内容，不报伪成功。
