# 知识库图片识别实施计划

## 目标

知识库导入遇到图片、扫描 PDF 页面或 Office 内嵌图片时，先使用已配置且可用的多模态 AI 识别；AI 未配置、不支持图片、请求失败或没有读出文字时，回退到本机 PaddleOCR。删除 Windows Media OCR。原文件继续保存在本机，AI 只收到实际待识别的图片，不上传整份文档；未读出的内容必须在来源告警中如实说明，不得标为已识别。

## 步骤

1. 为 AI 图片识别接口和 OCR 结果回填补失败优先测试：区分 provider 对图片的支持、AI 空结果/错误、本机 OCR 空结果/错误；确保图片 media 只附在用户消息。
2. 增加知识库专用图像识别调用：读取当前已保存配置与凭据，限制输入为受支持的图片，提示模型忠实逐行转录，禁止总结或补写；AI 失败返回可回退状态。
3. 将文档解析器改成可接收逐页/逐图的 OCR 结果，并保留原有 DOCX 锚点和来源顺序；删除 Windows OCR 实现、WinRT OCR 测试和仅为 OCR 引入的 Windows crate features。
4. 在资料导入流程中加入 AI 优先识别与 Paddle 本地兜底，涵盖单图、扫描 PDF、DOCX/XLSX 内嵌图；每种结果/错误清晰显示，原件和既有文字不受影响。
5. 更新隐私说明、README/发布说明与工作记录；进行单元、集成、构建和全套仓库门禁。只有实际 OCR 模型运行成功后才报告 Paddle 已实测。

## 验收标准

- 多模态 AI 成功时不会调用本地 Paddle；AI 不支持、无凭据、失败、空结果时调用 Paddle。
- Paddle 失败或没有文字时保留原件并给出具体告警，知识条目不得伪装成可检索。
- 图片和扫描页按稳定标识写回正确位置；DOCX 中的图像识别文本仍插入原图片锚点。
- Windows OCR / WinRT OCR 相关实现和测试完全移除。
- 隐私文案明确 AI 视觉识别只发送待识别的图片；不会发送整份源文件。
