# 本机知识库与 AI 问答实施计划

**目标：** 用户可以导入多种现有解析器支持的工作资料，搜索和提问时同时检索资料及实时已保存流程，答案引用可回到原件或流程；证据不足时不编造。

**架构：** Rust/Tauri 拥有导入、解析、事务、FTS 检索、流程读取与引用验证；React 展示资料和问答。原件沿用 `content_assets`，独立元数据/解析全文/段落分块进入正式迁移；SQLite FTS5 trigram 是派生检索索引。AI 查询改写与答案都复用既有服务商设置与凭据，不增加供应商或服务。

**边界：** 不改现有 AI 流程生成、待办、提醒或云同步协议。独立资料本机保存并随完整备份/恢复；现有云同步只同步备忘/流程，界面必须说明独立资料不会云同步。本机全文检索不声称 vector/embedding 语义召回。按 AGENTS.md 在当前主分支工作，用户已要求提交并推送此仓库每轮成果。

**设计依据：** [知识库设计](../../design-knowledge-base-2026-10-04.md)、[技术调研](../../knowledge-base-research-2026-10-04.md)。

**执行状态（2026-10-04）：** 核心实现与本机门禁已完成：迁移与索引、原件导入、现有文件解析器及 Windows 本机 OCR、实时流程证据、AI 引用校验、页面导航和完整备份均已落地。当前实现使用 FTS5 trigram 加 AI 查询词扩展，未增加向量语义检索。外部 AI 服务的真实账号调用、安装包中的手工 WebView2 验收及推送后的 GitHub Actions 状态以本轮工作记录中的实际结果为准；不把单元测试冒充模型质量验证。

- 流程实时搜索不可建立易失效缓存：只读当前 `memo_documents` 并在答案发出前二次核验版本。
