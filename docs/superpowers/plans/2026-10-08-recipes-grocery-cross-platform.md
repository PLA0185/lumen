# 食谱、热量与采购：实施和验收记录

## 目标

为 Windows 与 Android 增加食谱、每日饮食和训练热量记录、采购清单及多格式导入；围绕 Apple HIG、Android 自适应布局和 Windows Fluent 的当前官方指南，使用同一套可访问设计基础并按平台调整交互。

## 交付内容

- **在线热量核验**：Tavily 获取公开网页证据，配置的 AI 只根据该证据规范食物名称、每 100 克热量和来源。来源链接随候选展示；没有新候选或候选过期时不写入。改食物必须重新检索；改克数沿用当时保存的来源重新算。热量乘法在本机确定性计算。
- **每日记录与食谱**：手动设置每日目标；早餐、午餐、晚餐、加餐、计划/实吃和训练消耗分开显示；食谱配料需要在线核验，能安排进某天并合并到采购清单。
- **采购导入**：手动维护待办、数量、单位、分类、备注和完成状态；本机识别或 AI 整理可选。接受 PDF、DOCX、XLSX/XLS、图片、CSV/TSV、JSON、HTML/XML、Markdown、LOG 与文本；单文件最多 20 MiB。导入先预览，AI 结果可编辑/取消，只有确认后才写库。
- **数据安全**：迁移 0014 通过现有一致性快照机制；完整备份升至格式 8。饮食表仅进入现有“全部业务数据”云同步范围；任务-only 与备忘/流程-only 排除饮食表。AI 和 Tavily 密钥保存在各自设备的系统安全凭据库，不随备份或云同步；临时食物候选仅保存在本机。
- **平台界面**：Android 窄屏使用五项底栏和“更多”抽屉，宽屏切到侧栏；触控目标、系统安全区、键盘焦点和减少动画均有样式支持。Windows 保留持久侧栏、顶部命令区与鼠标/键盘密度。复用现有 SVG 图标与主题令牌，不复制 SF Symbols 或 Apple 专有视觉效果。

## 验收结果

- 前端：类型检查、374 项 Vitest、Vite production build 和 ESLint 均通过。
- Rust：格式检查、573 项库测试通过，4 项按项目既有标记忽略；Clippy 全目标、全功能且 `-D warnings` 通过。
- Android：ARM64 Release Rust 交叉编译与 Gradle APK 打包已完成；构建产物和签名状态见 `docs/work-log.md`。
- 跨平台自动化覆盖包括 Android WebView / Windows 平台识别、饮食汇总、在线候选约束、换食物原记录保护、采购解析/预览、完整备份往返和云同步范围。

## 未验证边界

本机没有连接 Android 模拟器或手机，APK 未做实际安装、触控与窄屏目测验收。也没有用户提供的 Tavily API Key 和 AI 服务凭据，因此没有执行真实联网热量查询；服务失败和候选校验由本地行为测试覆盖。具体证据与限制记录在 `docs/work-log.md`。
