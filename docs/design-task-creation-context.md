# 从所在位置新建任务

原先快速添加不读取所在视图的条件。在“今天”新建且不填计划日期时，任务虽然
保存成功，却被“今天”的计划日期筛选排除。修复后默认值跟随创建入口：

| 入口 | 默认归属 |
| --- | --- |
| 今天 / 明天 | 相应本地日期的全天计划 |
| 本周安排 | 今天的全天计划，属于当前自然周 |
| 周 / 月 / 季度 / 年任务 | 对应 period_type，不强加具体日期 |
| 日历 | 当前日历锚点；点击某日后沿用那一天 |
| 项目、分类、标签旁的加号 | 相应 project_id / category_id / task_tags |
| 收件箱、全部任务、看板 | 普通未完成任务，不强加日期和周期 |

日期与周期在保存前可见、可改，也可清除日期；自然语言日期优先于默认值。
保存后恢复当前视图默认值。切换视图时，尚未手动修改的日期和周期跟随新视图。
清除日期保存时会说明任务已进入收件箱。

项目、分类、标签原本是组织管理页，并不存在一个已选中的任务归属。现在在具体
条目旁提供“新建任务”入口；表单显示“新建到：…”并在管理页下方显示该归属的
任务列表。列表使用真实查询、总数与分页、批量子任务查询和 mutation 刷新，
支持既有编辑、完成、复制和删除流程。点击侧边栏“标签”直接进入标签管理。
组织管理页顶栏新建按钮不猜测归属，使用条目旁的加号；历史/设置/统计页不提供
会被当前页面隐藏的新建按钮，Ctrl+N 转到收件箱。

重复创建也保留项目、分类和标签。周期任务的重复归属使用 RRULE 扩展
`X-LUMEN-PERIOD=WEEK/MONTH/QUARTER/YEAR/DAY` 保存在系列与规则分段中。
首个实例与后续物化实例都写入既有 tasks.period_type；编辑器回显不丢字段，
没有修改数据库结构。

工作日规则仍然过滤执行日期：在休息日创建且开启双休/节假日过滤时，首次执行
可能在之后的工作日，保存前的发生预览会显示实际日期。

验证入口：`tools/verify_creation_context.py`。脚本只允许外部隔离数据库，逐个
真实点击新建入口，核对数据库归属及对应列表/日历中的任务文字；也覆盖周期内
重复任务与收件箱无日期任务。界面请求门禁恢复 StrictMode 效果重新挂载时的
激活状态，避免日历和组织管理页一直等待旧请求。
