# Lumen 多电脑自动同步设计

日期：2026-09-29。状态：**研究方案；产品功能尚未实现**。本轮不增加伪按钮、不执行用户数据
上传、不修改生产库。目标与提供者选择见 [官方调研](api-research-cloud-sync.md)，IPC 与存储
接口见 [接口契约](cloud-sync-api.md)。

## 一、用户可感知的结果

用户进一步明确：主要同步「备忘与流程」，在家编辑，公司上班打开可查看。因此首个可用版本
聚焦 **memo_documents 的备忘和顺序流程**，不要求先完成任务、重复、附件及全部 19 表的同步。
下文其它业务表的方案是范围扩展要求，不属于这个首版的完成声明。当前流程是已有编号步骤与
箭头的顺序流程，不代表新增了自由画布 / 任意分支流程图。

公司和家里电脑都保留完整本地数据，断网也能新建、完成、删除和编辑。联网后自动交换修改。
不同任务的修改都保留；同一项并发修改保留所有版本，在「同步冲突」中比较后选择。
同步未完成、断网、重新登录、配额不足与存在冲突分别显示，不能统一显示一个成功绿勾。

首版每个本地数据集只连接一个网盘 / 一个同步空间，所有设备加入同一空间。默认未启用，
首次连接由用户选择并看到同步范围；关闭同步保留本地数据。更换目标需要先处理待上传内容，
明确是接续同一空间还是建立新空间，不能把旧队列发给另一个账户。

备忘与流程的拟定保存行为：输入停顿约 1 秒后自动保存合法草稿到本机，立即进入持久上传队列；
手动「保存」会立即触发。上传只合并约 1–2 秒的短时间连续修改，不等待周期备份。空标题等
校验错误、版本冲突或本地落盘失败明确显示，并保留草稿；不能把无法保存的编辑标成已上传。
离开编辑区先尝试完成本地保存，失败时沿用未保存离开提示；上传失败不丢本地内容。

公司端启动 / 打开「备忘与流程」时立即检查远端，打开记录时先显示本机缓存并显示正在检查；
拉取成功自动刷新阅读正文。打开中的编辑稿不被后台替换，收到远端版本时保留稿并显示冲突。
在线期间默认每 30 秒检查轻量设备提示，窗口重新获得焦点时再检查；全部设备请求共享预算，
限流时显示重试时间。这不是强实时推送保证：启动前、断网、配额不足或提供者退避时会延迟。

保存状态分别显示「本机已保存，待上传」「已上传，时间」「上传失败，可重试」，另显示
「已检查云端，时间」。家里端上传成功不代表关机中的公司端已经下载；公司端要联网运行 Lumen。

同步由 Rust 后端运行。主窗与浮窗共用同一个作业和状态，程序关闭时不承诺同步；后台只在
Lumen 进程仍运行时工作。休眠 / 恢复与网络恢复触发检查，按服务商退避，不抢占普通本地写入。

## 二、现有代码能复用什么、还缺什么

| 现有实现 | 可复用与限制 |
| --- | --- |
| `db.rs` SQLite WAL、一致性快照 | 继续使用本地库；迁移前快照失败必须中止 |
| `backup.rs` 格式 3、19 张业务表的读事务导出 | 可做首次连接前安全备份和人工灾难恢复；恢复是整体替换，不能后台调用它来合并 |
| `tasks.sync_rev` / `sync_state` | 仅预留字段；没有覆盖其它表，也没有因果版本或删除记录，不等于同步引擎 |
| `memos.rs` revision 条件保存 | 可阻止过时草稿写入；该数字只在本机递增，不能比较两台电脑的先后 |
| `ai.rs` reqwest、keyring 模式 | 复用 HTTP 客户端的代理 / TLS 与系统凭据管理器，不把令牌传给 React |
| 重复模板、分段、例外、跳过、重建队列 | 同步规则与手工例外，重新生成派生数据；不能仅同步可见实例 |
| 硬删除及级联 | 子任务、标签关系、依赖、提醒、附件、目标及永久删除等需要墓碑；不能只轮询 `updated_at` |

生产库现有迁移 0001–0008 不改字节。同步持久状态必须通过新正式迁移增加；新增迁移之前
仍走原有一致性快照。不移动数据库到网盘，不复制正在运行的 `.db` 当作同步包。

## 三、同步数据与本机状态的边界

不是把整个格式 3 备份原样上传。同步数据采用稳定身份和显式字段白名单：

| 业务表 / 数据 | 协议身份与处理 |
| --- | --- |
| projects / categories / tags | UUID；同名不同 UUID 遇到数据库唯一约束时提示组织冲突，不能按名字悄悄覆盖 |
| tasks（普通任务） | UUID；标题、正文、时间、归属、状态等可移植业务字段 |
| subtasks | UUID + 父任务身份；独立子任务的修改可并存；父任务完成规则要在最终事务状态重算 |
| task_tags / task_dependencies | 用两端稳定身份作为复合键；解绑 / 删除要有墓碑；合并后再次检测依赖循环 |
| reminders | 同步用户的提醒规则；`fired_at` 等发出状态按设备保存，防止同步后重复通知 |
| attachments | 同步附件描述与内容摘要；复制模式的文件需运输、校验并写入受控本地目录 |
| task_series / task_series_template / task_series_tags / task_series_segments / task_series_skips | 系列 UUID 为共同身份；规则、模板、分段与跳过作为具有完整一致性约束的业务组 |
| task_series_rebuilds | 本机派生工作队列，不直接传输；规则接收后在本机重新创建 |
| 重复任务实例 | `(seriesId, occurrenceKey)` 稳定身份；随机实例 UUID 不能当跨设备唯一身份 |
| memo_documents | UUID；正文与步骤数组原子版本；首版并发编辑整篇提示冲突，不自动拼接流程 |
| focus_sessions | 终结的专注历史可同步；运行 / 暂停中的计时器、恢复起点与通知归本机 |
| goals | UUID；新增、变更及硬删除均进入同步日志 |
| settings | 首版默认本机保留；只在明确增加便携偏好白名单后同步，不复制所有设置 |

设备 ID、窗口坐标 / 尺寸、自启、快捷键、AI Key、OAuth / WebDAV 凭据、附件绝对路径、
日志、备份目录、迁移信息与同步队列不随业务数据传播。账户标识与本机关联设置也不进入普通
完整备份；人工恢复后要检测新的同步世代，不能复用旧 outbox 直接传播整库删除。

附件引用模式指向原电脑文件：另一台电脑显示「原电脑本地文件」，不得伪称可打开。
只有用户选择受控复制的附件才上传正文；内容未传到云端时任务可以先同步，但该附件明确显示
未同步 / 下载失败。默认单个受控附件限制 20 MiB，是产品建议值，不是服务商官方上限。
附件数据运输及上述身份映射未验收前不能把全范围自动同步作为已完成发布。

## 四、因果版本与冲突

不用「最后修改时间较新覆盖」：两台电脑的时间可以有误差。每台设备有独立随机 ID 和在
SQLite 中持久递增的批次序号；批次带已观察的设备版本向量。向量用于判定因果顺序，UTC
时间只用于展示。

同一实体保留所有未被后续因果版本取代的版本：

- B 已看到 A 的修改，随后编辑：B 的新版本取代该已看到的版本。
- A、B 都从共同状态离线编辑：两个版本互不包含，均保留，标为冲突。
- 不同实体：分别合并，不能以整个数据库产生「二选一」。
- 并发修改内容完全相同：界面可显示一个值，但保存两条因果来源，避免下一轮重复报冲突。
- 删除是一个带版本的墓碑；删除与并发修改同时保留供用户决定，不能自动复活或静默删掉。
- 解决冲突产生观察了全部当前候选的新版本；旧冲突归档。用户操作期间有新候选 / 本地编辑，
  比较令牌失效并重新显示，不把旧选择盖到新内容上。

示例：公司端将任务标题改成「周五交付」，家里端同时改成「周六交付」。同步后显示两版本，
允许选其一或手动整理成新版本。普通任务 / 备忘可经明确「保留两份」创建新身份；重复系列、
依赖和其它对象的复制需要业务映射，首版不提供看起来能用的万能复制按钮。

这里采用实体完整版本作为首版冲突边界，字段互不重叠的并发修改也可能要求选择。这是保守的
明确限制：保留版本比未经验证地拼接正文、日期、状态与规则安全。以后增加字段合并需独立测试。

[协议验证模型](../tools/verify_sync_protocol.py) 只演示一个实体的因果保留、删除与解决冲突。
它不是生产同步模块，也没有验证上述 SQLite / 重复规则 / 附件集成。

## 五、同步事务与崩溃恢复

拟新增本地持久结构：设备 / 目标元数据、因果版本、待发送 outbox、已接收 inbox / 游标、
冲突候选和本机附件映射。名称与完整 SQL 在实现迁移时确定，本轮没有加入这些表。

本地业务写入与 outbox 记录必须处在**同一 SQLite 事务**，所有写入路径都要覆盖：普通任务、
批量操作、AI 草稿落库、子任务自动完成、重复规则、解绑、回收站、永久删除、目标、备忘及附件。
多表操作一个批次，记录事务结束前的最终状态，不传输半个业务事务。级联删除也要留下必要身份。
计数器与原始待发送内容同事务落盘；加密后的待上传字节冻结，重试不重造事件 ID 或加密 nonce。

接收方先下载到仓库外临时文件，检查版本 / 空间 / 长度 / 摘要 / AEAD / 因果依赖 / 业务字段，
然后在同一事务保存 inbox、候选版本、业务合并与游标。缺少父实体、规则组、摘要不符、循环
依赖或未知格式不进入业务表；保留错误，不标已接收。不确认未持久提交的批次。

远端已成功、本地还没确认时崩溃：按原事件 ID 重试，已存在且摘要相同即幂等；相同 ID 不同
内容是设备克隆 / 协议损坏，立即停止该源，不覆盖。每个设备的批次按连续序号应用，缺号或缺
因果前置时等待补齐；其它独立源可以继续，不能跳号后永久抛弃前置内容。

网络操作期间不持有数据库写锁。接收的业务写入与本地 outbox 捕获要区分来源，避免无限回传
同一远端版本；业务规则导致的新用户可见变更需单独产生因果后继，不能默默漏传。

## 六、网盘上的文件布局

下面是 Lumen 拟定协议，不是 OneDrive / 坚果云规定的目录：

```text
<提供者的应用目录>/spaces/<workspaceId>/
  protocol.json                          # 不可变空间、协议版本、加密参数
  devices/<deviceId>/descriptor.json      # 设备公有描述，注册后不变
  devices/<deviceId>/head.json            # 单设备写入的发现提示，非数据真相
  devices/<deviceId>/journal/<bucket>/<seq>-<batchId>.bin
  checkpoints/<checkpointId>.bin          # 后续压缩 / 新设备初始化，带验证边界
  blobs/<digestPrefix>/<cipherDigest>.bin # 用户选择复制的附件
```

每个事务一个批次文件，单文件只由一个设备创建，发布后不改。桶号由 `(seq-1)/256` 的整数商
计算，所以一个 journal 桶最多 256 个正常批次文件，直接定位下一桶，不列举无限增长的桶根。
建议批次最大 4 MiB、空间最多 32 个活跃设备；超过时明确报边界，不能截断列表。
这些是拟定协议限制，仍需压测和真实存储验证。

`head.json` 仅加速发现；读取后必须验证对应批次与前一摘要链。应用不能因 head 滞后就宣称
所有设备都已同步，也不能因用户删除文件就把业务任务删除。业务删除只来自经过验证的墓碑。
发现远端重置、缺失目录、损坏、同名摘要不同或链倒退时暂停该目标，保留本地修改并提示恢复。

不同设备不竞争写一份全局 `latest.json`。OneDrive 驱动用失败而非覆盖的上传语义；WebDAV
先探测条件创建。单设备提示允许该设备替换，但任何跨设备共享可变元数据必须另做经过验证的
并发控制。**未验证 CAS / LOCK 时不能把它们写成协议可靠性前提。**

首次加入空间需用户指定既有 workspace；新建空间用随机 UUID 和明确选择。新设备从经过校验
的检查点及其覆盖向量读取后续日志，或首版读取完整日志；首次扫描只展示预览，保留本地不同
UUID 的记录，不能调用整库恢复。相同身份不一致作为冲突。检查点、日志回收及设备退役方案
需要实际实现与验收；首版在此之前保留全部日志，不根据文件年龄删除墓碑。

## 七、重复任务、父子任务与通知的特殊规则

- 独立设备生成的同一次重复任务会有不同随机 UUID。传输时使用稳定 occurrence key，并对
  子任务、提醒、标签和附件引用重新映射本地 ID；不能用 SQL `INSERT OR REPLACE` 覆盖。
- 生成模板子任务要有跨设备稳定模板槽位或派生身份；当前随机子任务 ID 不足够，需要正式
  数据映射设计。先验收「两设备同时展开相同系列只产生一个实例」才能开放同步。
- 规则、分段 / rule_version、模板、系列标签与 skip 联合校验。两个端分别改未来规则，保留
  整组候选，由用户选择；普通整数 rule_version 不能证明跨设备先后。
- 已手工修改的例外与已完成实例不得因远端重建而消失。派生删除和用户单次取消要区分：只有
  后者生成 skip；规则变化后的重建队列本机持久重试。
- 全子任务完成后的父任务状态要与当前规则一致；不能只合并一条 status，让未完成子任务的
  父项意外显示完成。手动完成与子任务触发完成需有可验证语义。
- 提醒触发状态与正在运行的专注计时不跨设备启动。首版提醒逐设备发出，UI 要说明可能多端
  提醒；只有另做提醒所有权才可以承诺跨设备仅一次。

## 八、安全、节流与用户控制

凭据复用已有 Windows 凭据管理器模式。不得经普通查询返回 token / password，且不进入日志、
完整备份、AI 输入、同步包。授权和存储请求均在 Rust 中，不扩大前端 CSP。

业务资料包含公司流程，建议**首个可用版本默认端到端加密**：随机空间密钥、经审核的 AEAD
库、随机 nonce、协议 / 空间 / 设备 / 序号作为认证数据；跨设备使用用户恢复口令包装空间
密钥。口令派生使用成熟 KDF，参数设定与资源上限需安全审查，不手写密码算法。服务商令牌
与加密密钥是两套东西，HTTPS / keyring 都不等于端到端加密。

完整加密信封、密钥轮换、恢复口令遗失的说明和双设备解密测试属于发布阻断项，本轮只定义
这些要求，没有实现加密或承诺网盘无法读取本轮尚未产生的同步内容。

备忘首版采用前述 1–2 秒上传合并、启动 / 阅读 / 回焦立即检查及在线 30 秒轻量检查，
这是产品设计参数，不是官方延迟保证。两端常在线时，若每次各读 2 个设备提示，30 分钟约
240 次提示读取；实际列表、下载、写入与重试也计入预算，增加设备后必须降低轮询频率。
请求预算覆盖多个设备总量，429 遵守 Retry-After，5xx / 网络错误指数退避加
抖动；401 只刷新 / 重登，403 与配额问题停止重试提示原因。手动同步也遵守已有退避。

用户可查看待上传数量、最后成功检查时间、冲突数量、失败原因，暂停 / 手动重试 / 断开。
断开保留本地数据和远端空间，删除凭据失败要返回错误，不能宣称已退出。

## 九、实施次序与真正的完成标准

1. 先实现备忘 / 顺序流程：正式迁移、备忘保存 / 删除恢复的原子 outbox、自动本地保存、稳定
   UUID、删除版本、公司端启动与阅读正文刷新；备忘当前为单行原子数据，完整步骤不拆成半个流程。
   使用两个隔离 profile 验证，不动生产数据。
2. 实现备忘冲突保存 / UI / 比较令牌、首次加入预览、安全备份、加密与 WebDAV 驱动；在坚果云
   专用目录验证及时上传、离线补传及家里 / 公司切换。之后再做 OneDrive 登录与应用文件夹联调。
3. 首版界面明确范围为「备忘与流程同步」，不得暗示任务 / 附件也已同步。必须通过下面的
   首版验收，才在安装版开放；其它表按接下来的扩展步骤逐步实现。
4. 扩展任务时实现全部业务写入的原子 outbox、跨设备身份与删除记录；先用两个隔离 profile
   和本地目录驱动验证，不依赖真实账号来替代协议测试。
5. 扩展业务事务验证、组织唯一约束、完整规则组与全范围冲突解决。
6. OneDrive 驱动分别验证个人与工作账号及 AppFolder 权限；不默认承诺管理员禁止的组织账号可用。
