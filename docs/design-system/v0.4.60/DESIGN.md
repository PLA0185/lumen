# Lumen Workbench — 0.4.60 设计合同

## 设计方向

- **产品工作：** 在一个本地优先的工作区里安排任务、回看日期、执行重复事项、维护业务流程和检索资料。
- **主要用户：** 每天反复处理运营计划、跨日期任务和可复用业务步骤的中文用户；主要使用 Windows，外出时用 Android。
- **语气：** 安静、务实、可扫读。任务列表保持信息密度，资料编辑区给长内容留空间。
- **记忆点：** 主工作区像“当日工作台”：日期安排、任务执行清单和当天观察并列；月历选中一天时，右侧即时呈现当天任务，可直接从那里新建。
- **设计约束：** 保留现有业务行为、IPC 和数据；不引入新的 UI 依赖；桌面和手机布局分别设计；颜色不能承担唯一状态表达；重要任务动作支持键盘和触屏。

## Skill 要求如何落到产品上

- `apple-design` 在这里指导直接操作和可预期反馈，不要求把 Lumen 改成仿苹果外观。日期选择会立刻联动当天安排；任务完成与目录选中在操作位置反馈；现有拖拽按手势直接改期；减少动态效果、透明度和高对比偏好都有独立规则。
- `frontend-design-direction` 的方向合同落实为“本地优先的运营工作台”、先看日期和待办、不同页面用不同工作结构，并把加载/空/失败/部分/成功/权限作为验收状态。窄屏目录使用页面自然滚动，避免资料区内部再套一个小滚动条。
- `design-system` 先审计既有 CSS 与十个维度，再记录 Things、Todoist、Linear 三个产品的具体交互观察；令牌同时落在 JSON 与 CSS，预览是无依赖 HTML。参考资料只借用“日期与任务并列”“同一任务跨视图”“列表与详情主从层级”，不复制其视觉品牌。
- `codebase-design` 侧重在现有模块边界内完成结构变化：当天概览独立成 `TodayOverview`，知识库继续通过原有导入/检索接口工作；重排界面不另造一套数据状态。
- `accessibility` 要求落实为文字与图标共同传达状态、键盘可聚焦日历格、焦点环清晰、窄屏主要触控目标至少 48px，并检查浅色、深色和系统减少动态效果。

## 页面合同

| 页面 | 用户先看到 | 主要操作 | 层级与响应式 |
| --- | --- | --- | --- |
| 今天 | 一周日期、当天待处理任务、逾期/进行中概览 | 完成任务、打开任务编辑、新建任务 | Windows 为清单 + 当天检查栏；手机先呈现当天任务清单，再查看概览和统计 |
| 本周安排 | 按实际计划日期排列的各日清单 | 完成任务、为指定日期新建、改期 | 日期成为分组标题；无日期任务单独收纳 |
| 日历 | 月网格与当前选中日期的安排 | 切换日/周/月、逐日浏览、该日新建、拖动改期 | 月视图桌面双栏；窄屏月历后接当天安排 |
| 流程/备忘 | 左侧资料目录、右侧正文/步骤画布 | 新建、搜索、编辑、导入/导出、查看原图 | 桌面固定主从栏；手机目录可滚动、正文自然堆叠 |
| 知识库 | 资料范围与问答并列、来源证据随回答展开 | 选择资料、提问、查看来源 | 桌面侧栏 + 工作区；手机纵向排列 |
| 设置 | 稳定的类别导航和当前类别内容 | 选择设置类别、保存现有设置 | 桌面类别栏固定在左；手机类别变成可横向滚动的吸顶栏 |

## 0.4.59 视觉审计

审计基于 [0.4.59 桌面深色预览](../evidence/desktop-dark.png) 和现有真实 JSX/CSS。该版覆盖面广，但工作区仍是原有的通用侧栏、顶栏与单列列表，正如用户反馈，视觉变化主要来自颜色和控件表面，因此不构成完成的产品重构。

| 维度 | 分数 / 10 | 观察 | 0.4.60 改动 |
| --- | ---: | --- | --- |
| 色彩一致性 | 7 | 语义色齐全，深浅主题有同一组角色 | 延续语义 token；颜色仍只作辅助信号 |
| 字体层级 | 5 | 页面标题明确，但列表、指标、辅助说明的层级相近 | 为页内清单标题、日期、侧栏数字与说明设定独立层级 |
| 间距节奏 | 5 | 间距接近统一，但所有视图落在相同外边距和列表密度 | 按工作区、日期组、检查栏分区，并保留紧凑任务行 |
| 组件一致性 | 6 | 表单控件风格统一，页面却共享同一内容骨架 | 为今天、本周、日历、资料和设置建立各自的布局模块 |
| 响应式 | 5 | Android 有底部导航，复杂工作区在窄屏下仍只是压缩/堆叠 | 为月历、当天面板、设置导航、资料目录明确重排顺序 |
| 深浅主题 | 7 | 主要颜色角色覆盖两种主题 | 新结构只用现有语义变量，不新增仅深色有效的颜色 |
| 动效 | 4 | 状态反馈有限，主要依赖统一过渡 | 交互采用短、可中断的反馈；减少透明材质并尊重减少动态偏好 |
| 无障碍 | 6 | 具备焦点态、标签和语义控件；小型日期操作的点击区需关注 | 新增入口为真按钮；保留键盘顺序、文字状态和触控尺寸 |
| 信息密度 | 4 | 全局工具栏挤在同一行，页面重点容易和工具混在一起 | 新建任务移至常驻导航；日期清单按工作语义拆分 |
| 完成度 | 5 | 颜色和卡片风格较完整，空列表以外的页面结构差异不足 | 为核心视图引入可操作的检查栏、日期分组与选中日侧栏 |

## 参考观察

外部产品只用于提取具体交互原则，不复制品牌和视觉：

- [Things：新版本功能](https://culturedcode.com/things/features/) 把 Today 的日历事件与任务放在同一日程，并支持直接把新事项放到具体日期；启发当天清单与日期上下文并排。
- [Todoist：Calendar layout](https://www.todoist.com/help/todoist/features/use-the-calendar-layout-in-todoist-lPHRQTu0o) 把周/月网格、拖动改期和在某日新建放在同一工作面；启发月历旁显示选中日安排，并保留逐日创建入口。
- [Linear：Inbox](https://linear.app/docs/inbox) 与 [Triage](https://linear.app/docs/triage) 将需处理通知与普通工作区分，并允许从队列项目进入上下文执行动作；启发资料目录与正文分栏，以及错误/权限状态保留可恢复入口。

## 动作、材质与文字

- 操作反馈在按下时出现；完成、选中、聚焦和拖动目标均不只靠颜色区分。
- 任务、资料正文保持不透明；磨砂只用于导航、工具栏等结构层，不把多层玻璃卡片叠在一起。
- 常规控件至少 42px；Android 触控按钮采用 48px 目标。键盘焦点始终可见，图标按钮有可读名称。
- 使用系统字体与现有字体大小设置。页标题收紧字距，正文使用舒适行距；长中文标题允许换行或省略并可查看完整内容。
- 普通状态转换短促；拖拽沿用现有直接操控逻辑，不加脚本化弹跳。开启“减少动态效果”或系统减少动态后去掉位移过渡；减少透明度时改用不透明表面。

## 状态合同

| 状态 | 触发与反馈 | 安全下一步 |
| --- | --- | --- |
| 加载 | 列表保留骨架或稳定的已有内容，标注读取中 | 等待或按现有入口重试 |
| 空 | 区分无任务、无搜索结果、无当天安排、无资料 | 展示对应的真实新建/清除筛选入口 |
| 错误 | 显示具体错误内容，不隐藏失败 | 使用对应重试/恢复操作 |
| 部分 | 分页说明已加载数；资料解析提示、缺失附件和来源范围可见 | 继续加载、重试解析或核对原件 |
| 成功 | 保存/完成操作显示现有 toast 或列表更新 | 继续当前工作；只有后端提供撤销时才显示撤销 |
| 权限 | AI、系统通知和云连接只在功能触发处说明访问边界 | 去设置配置或退出当前流程 |

## 验收视口与证据

目标视口为 Windows `1440×900` 和 `1280×800`；手机为 Android `390×844` 与窄屏 `360×800`。本轮逐一检查了设计预览在四个目标视口的当天清单、周安排、月历、流程/备忘目录—正文、知识库问答、设置导航及手机补充导航；六种内容状态另有独立预览。所有截图都是明确标注示例数据的静态 HTML 设计原型，存放在本目录的 `evidence/`，只用于检查信息层级、布局、配色、键盘焦点与交互样例，不读取或写入 Lumen 数据。

这不等于真实 Tauri 应用或 Android WebView 的端到端验收。桌面安装窗口、Android 设备、真实数据库加载/保存/故障、辅助技术朗读、系统高对比度/减少动态/减少透明度组合、用户真实长文本与附件布局仍未验证。核心文字/表面/按钮配色的 WCAG AA 对比计算结果及 prototype focus 截图记在 `evidence/README.md`；实际设备边界保留在 `evidence/report.json`。
