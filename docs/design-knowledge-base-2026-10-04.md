# 知识库与 AI 问答设计

状态：按用户要求调研并直接实施；本文件定义本轮要交付的可用范围与验收条件。调研依据见[知识库检索调研](knowledge-base-research-2026-10-04.md)，逐项执行见[实施计划](superpowers/plans/2026-10-04-knowledge-base-query.md)。

## 用户目标

用户可以把工作文件加入个人知识库，或直接问 Lumen 已保存流程里该怎么处理。资料沿用 Lumen 本机解析能力；解析后自动生成保留章节、文件名和文字位置的检索分块。提问使用自然语言，AI 根据实际命中的原文回答并提供可核对来源；没有证据时明确说明没有检索到。用于判断“下一步”的流程顺序以用户保存的步骤为准，不推断任务现实进度。

## 数据与检索

- 文件原件进入现有 `content_assets`，独立来源表记录文件信息、内容哈希、完整提取文字、解析状态/告警及创建时间；解析失败的原件保留并显示失败原因，不被当作可检索资料。
- 解析全文按标题和段落生成带字符范围、章节/页签定位的连续片段。普通图片、扫描 PDF 页面及 DOCX/XLSX 内嵌图片先交给已配置的多模态 AI 逐张忠实转录；AI 未配置、失败或无文字时回退到随 Windows 应用打包的 PaddleOCR PP-OCRv4。本机 Paddle 识别文字放回 PDF 页或原文图像锚点；两种引擎都失败时保留原件、显示告警并标记不可检索。导入整份文件不会上传；AI 视觉路径仅发送待识别的单张图片/扫描页。过长段落按有限长度拆分并保留交叠上下文。原文不被覆盖，片段不是 AI 改写的证据。
- FTS5 trigram 对标题、章节和正文建立本机索引，标题与章节加权。自然语言问答合并 AI 生成词、原问题/最近用户追问拆出的词，以及常见标签和打印同义词后执行本机检索；这样 AI 漏掉关键词时仍保留本机召回路径。1–2 字检索词有明示的短词路径。任何索引失败、解析失败或模型错误都向界面返回明确失败。
- 已保存流程不重复入库：每次按当前数据库内容搜索流程标题、章节、步骤、负责人和详情。流程证据记录当前 revision；文件证据记录来源 ID、原件 SHA-256 和分块定位。
- 候选流程超过一个时先呈现流程名、分类、步骤和原文片段，要求用户选择具体流程后再问，避免多个流程被混成一种操作。唯一流程命中具体步骤时，问答证据包含完整命中步骤和紧邻的下一步；选择范围后仍可同时检索独立文件。
- 只有真实检索到的片段会进入回答提示。每条命中由 Rust 创建 `E1` 等本轮 ID；AI 仅能返回这些 ID。引用未知编号、空答案或不合法结构化返回时报告错误，不显示未核验结论。
- 查询词分析与答案使用 AI 配置的单次输出上限，不设知识库专属低 token 截断；DeepSeek 有界 JSON 请求关闭可选推理，避免思考内容占掉正文预算。设置页最高可调至 384000 tokens（DeepSeek API 当前上限，最终仍受上下文总长度限制；其它模型遵守各自上限）。[DeepSeek Chat Completions API](https://api-docs.deepseek.com/api/create-chat-completion/)
- 返回前再次校验文件 SHA-256 与启用状态、流程 revision。来源更新或删除时拒绝返回旧答案；用户可重新提问。

## 界面

- 左侧增加独立“知识库问答”视图，包含导入多文件、资料列表、解析状态/告警、检索问答输入、本次页面对话、命中来源摘录和定位信息。
- 资料来源显示检索片段及章节/页码/字符位置，并可导出原件核对；流程来源可跳到备忘与流程中的对应记录/步骤。删除资料会删知识索引；若文件仍被流程引用，保留原件，避免破坏流程。
- 显示 AI 服务商的数据政策提示。提问时发送问题、对话必要上下文和有限命中片段；启用图片 OCR 的导入可能把待识别图片逐张发送到已配置的多模态 AI，不发送原始整份文件。
- 独立知识库是本机数据，包含在 Lumen 完整备份/恢复内；当前不会通过只同步备忘与流程的云同步传到其它设备。AI 服务未配置时文件搜索仍可用，AI 问答明确引导配置，不显示假 AI 结果。

## 不做的事与边界

- 不改造现有 AI 流程生成、任务创建、提醒、同步协议或文件导入路径。
- 本轮采用本机全文索引与 AI 查询改写，不宣称向量检索/语义 embedding；不增加向量服务、第三方 SaaS 或后台常驻服务。
- 解析器明确不支持的旧 DOC、PPTX、RTF、ODT 不会被当作已解析资料。Windows OCR 已从实现和依赖中删除；扫描 PDF 页面用 Windows PDF 渲染成图片，再按多模态 AI 优先、本机 PaddleOCR 兜底识别。未完成 OCR 的纯扫描 PDF 不能以仅有页码的空内容进入检索。
- AI 不知道领导实际完成了哪些步骤，也不能根据流程文本断言现实状态。询问“接下来”但没有给出当前进度时，只能指出可核实步骤并说明需要用户告知进度。

## 验收

1. 通过正式迁移的 FTS5 表支持中英文/中文子串、短词、标题权重、分段定位；SQLite 迁移前快照规则不变。
2. 导入支持的真实 fixture 后，原件字节/哈希保留、全文可搜、文字定位正确；不支持/损坏文档可见且标记不可检索。
3. 从实时流程记录搜到正确标题、章节及步骤；回收站与普通备忘不进入流程候选；多流程结果先澄清。
4. 无命中不会生成模型答案；结构错误、模型错误、未知引用和数据版本变化均明确失败；有效回答只展示当前检索证据。
5. 删除来源会从检索结果消失，不破坏被流程引用的原件；备份恢复后索引可用，旧备份仍可导入。
6. 全套前端/Rust 门禁及 GitHub Actions 实际通过；外部模型在没有本机可用凭据时标为未验证。
