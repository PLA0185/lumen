# 备忘与业务流程

侧栏「备忘与流程」用于公司业务学习。备忘保存术语、操作说明和资料清单；流程保存
按顺序执行的操作、每一步的负责人和注意事项。两者独立于待办任务，不参与任务数量、
完成率或日历统计。

## 使用

- 点击「新建备忘」填写标题、分类和内容。内容支持 Markdown 标题、清单、链接。
- 点击「新建流程」填写说明，再逐步添加操作标题、负责人及具体说明；可上移、下移、
  删除步骤。保存后显示编号卡片和向下箭头，帮助按路线查阅。
- 点击「保存并查看」后才写入数据库。保存失败保留草稿；切换记录、新建其它记录
  或通过侧栏、托盘离开时，未保存的修改会提示确认。
- 顶栏搜索匹配标题、分类、正文、步骤标题、负责人及步骤说明；分类下拉进一步过滤。
  点击「编辑记录」修改，「复制内容」复制成 Markdown。
- 删除进入本页面的「备忘回收站」，可恢复。这与任务回收站分别管理。

## 数据与恢复

正式迁移 `0008_memo_documents.sql` 新增独立表，沿用现有数据库迁移前一致性快照。
迁移校验和取 SQL 原始字节，因此 `.gitattributes` 固定旧 0001–0007 为 CRLF，
匹配本机原有校验和；0008 起固定 LF，避免 Git 检出规则导致后续升级误报迁移被修改。
正文和全部步骤保存在一行中，保存为单条原子 SQL；每次修改、删除、恢复递增版本号。
写入必须匹配打开时的版本，过时修改报冲突，不覆盖已保存的其它修改。

完整 JSON 备份增加 `memoDocuments`，包含正常记录和回收站记录。引入备忘时格式为 2，
自行审查补齐重复配置、专注历史及目标后升级为 3，防止旧程序导入时丢弃新数据。
可读取格式 1、2，但有重复系列却缺少持久化模板的旧备份会明确拒绝恢复。
旧备份缺失新字段时按空集合读取，
空集合不改变旧格式的校验和。恢复仍是整体替换：旧备份可能没有备忘，恢复预览明确
显示当前与备份数量并提醒覆盖。恢复前一致性快照和导入事务继续使用既有路径。

备忘和流程仅保存本机，不自动发送给 AI 或其它服务。Markdown 预览复用现有净化组件，
不执行 HTML 或危险链接。

## 范围与验证边界

当前流程是顺序路线，最多 100 步；没有条件分支、自由连线、拖动节点、图片附件、
流程转任务或 AI 自动生成流程。正文最多 10 万字，每步说明最多 5000 字。
保存是手动操作；强制结束进程时未保存的草稿不保证保留，完成编辑请点击保存。

自动化使用真实临时数据库验证保存、搜索、版本冲突、删除恢复、备份内容往返和旧
格式校验兼容；React 测试验证调序、保存失败保留草稿、放弃修改确认和安全预览。
`tools/verify_memos.py` 只允许显式的 `memo-test-data` 隔离 profile，以真实鼠标事件
验证桌面操作与原生备份恢复。测试会接管确认函数验证接受/拒绝行为，未验收原生弹窗
外观。复制按钮使用已有剪贴板插件；未进行实机复制验收，以保留用户当前剪贴板。
