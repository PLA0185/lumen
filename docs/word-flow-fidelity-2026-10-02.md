# Word 流程顺序、图片位置与 AI 忠实性修复

## 已确认的原因

2026-10-02 对用户提供的原始 DOCX、本机保存流程和导入代码进行只读核对。原文有 11 个正式编号章节、30 张正文图片，没有重复引用同一图片；旧生成结果却有 23 个步骤，并把 5 个图片资源重复放到不同步骤。原始材料没有「完成标准」「例外情况」「待确认」标签，旧步骤中分别新增了 23、4、8 处。

原因涉及两层：DOCX 导入只提取文字，再按 ZIP 条目顺序收集图片，丢弃了段落样式、图片关系和位置；AI 提示允许按业务推测重排、重复使用同一原图，输出校验又只检查资源是否存在，没检查归属及重复。只调整画布或只改一句提示都不能解决。

## 最终行为

- DOCX 正文解析保留段落的大纲级别，以文档内部图片关系解析实际图片位置；图片链接插在原文对应位置，与 ZIP 条目顺序无关。表格中的图片和非自闭合图片标签同样处理。
- 明确、连续编号的一级章节作为权威步骤：每章一张卡片，章节标题、操作正文及图片逐字沿用；介绍中的概览列表不会再次生成步骤。子标题保留在本章正文中。明确的负责人字段可以提取，未提供时留空。
- AI 提示禁止拆分、重排已有章节和无依据重复使用图片。已提取的文档正文只发送一次，文件提取说明不作为用户业务规则。程序最终依据原文章节构造步骤，模型返回的额外拆分、乱序或补写不能进入这些步骤。
- 没有明确章节的聊天整理仍使用 AI；重复图片引用超过原文实际出现次数时返回错误，不保存伪成功。原文明示多次引用同一张图时允许保留。
- 原文没有的完成标准、例外、待确认、材料清单等生成段落被过滤；原文明示的相同标签保留。普通编辑器不重复追加已经在识别正文内定位的图片。
- 原始 Word 和图片资源不改写；派生图片继续在完整生成校验成功后一次性落库，失败回滚。已有流程的修正必须通过带版本号的保存入口保留历史。

## 验证与边界

新增回归已实际观察失败：图片没有原位置链接、AI 3 步覆盖原文 2 章、未阻止重复配图、补写待确认、编辑器重复追加图片。修复后通过。

实际用户 DOCX 的验证数据保存在仓库外：独立 Python XML 读取生成章节/段落/图片名称清单，Rust 提取结果逐章对比标题、全部正文段落与图片顺序；没有把用户文档、数据库或截图提交到 Git。外部文档测试需要显式提供验证目录，常规 CI 不具备用户文档，标记 ignored；本机已显式运行。

当前章节保护识别 Markdown 中至少两章、明确连续编号的一级/二级标题；只有一个章节或没有这种结构的材料仍依赖模型整理，不能声称已消除所有模型事实错误。旧 DOC、页眉/脚注、原页面版式不在这次修复范围。图片备注与批注、卡片缩放/内联编辑、通用中文断行、流程切换、导图导出、完整快捷键及悬浮问答仍按已批准计划继续，未交付的不能算进本次修复。
